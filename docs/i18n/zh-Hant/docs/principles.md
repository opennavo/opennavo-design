# 原則

OpenNavo 應用管理的，是人們在自己電腦上在意的東西：裝了什麼、登入時執行什麼、刪掉什麼、什麼在聯網。介面先要讓人覺得平靜、可信，然後才談得上聰明。下面這些原則決定怎樣取捨，規範的其餘部分都是在應用它們。

## 1. 內容優先，介面框架退居其次

各層表面都接近中性色，彼此只差一小檔；邊框都是細線。顏色只用來表達含義——品牌強調色標出下一步要做的那一件事，狀態色表示狀態——絕不用於裝飾。如果一個頁面要靠彩色背景才顯得完整，說明層級出了問題。

- 兩套主題都是一等公民。深色是品牌的預設外觀，淺色並不是蓋在深色上的一層濾鏡。每個顏色令牌都分別帶有兩套主題的取值，兩套取值都在 CI 中檢查對比度（[顏色](color.md)）。
- 光暈和漸變只允許出現在兩個地方：功能主視覺和品牌標誌。在淺色模式下，它們更柔和。

## 2. 先說清會發生什麼，然後嚴格照做

任何會改動使用者電腦的操作，執行之前，介面都先用平實的話說明效果；有幫助時，再展示實際要執行的命令或檔案清單。按鈕寫明具體動作，如“Uninstall”（“解除安裝”）、“Move to Trash”（“移到廢紙簍”），而不是“OK”（“確定”）。“Nothing happens until you confirm”（“你確認之後才會執行”）是一句由程式碼兌現的承諾。

- 破壞性操作先確認，並預設採用可恢復的方式（先移到廢紙簍而不是直接刪除，先停用而不是移除）。
- 操作完成後，結果立即出現在使用者發起操作的地方（[互動模式 › 結果即時呈現](patterns.md#載入進度和結果)）。

## 3. 本地優先，並告訴使用者

從使用者電腦上讀取的資料只留在本機，除非使用者另作選擇。介面讀取敏感資訊（磁碟佔用、啟動項、網路連線）時，用一行說明交代資料的去向——通常是“Only on this Mac; nothing is uploaded”（“只在這臺 Mac 上處理，不會上傳”）。確實有資料要發往伺服器時，文案寫明是哪個伺服器。

## 4. 操作時介面保持穩定

使用者正在操作時，佈局絕不先清空再重新填充。在搜尋框裡輸入、改變排序、翻頁或後臺重新整理時，都保留之前的內容，直到新內容準備好；可選的文字行提前預留位置。骨架屏只用於檢視的首次載入。重新整理失敗時，保留最後一次成功載入的內容，並用橫幅說明。介面一閃，使用者就會以為“應用壞了”。

## 5. 尊重平臺習慣

- **macOS**：使用原生的紅綠燈按鈕和標題欄行為；許可權透過直達系統設定相應面板的深層連結申請；選單欄專案的行為與系統一致（使用模板影象，絕不啟用應用或搶走焦點）；鍵盤快捷鍵遵循 Mac 的習慣（⌘K 搜尋、⌘, 開啟設定、Escape 關閉）。
- **網頁**：頁面由伺服器快速渲染，可以快取和分享，因此 HTML 中沒有任何內容取決於訪客；每位訪客各自的選擇（主題、語言建議、隱私授權）都在瀏覽器中生效。
- **原生工具包**（SwiftUI、Flutter）使用同一套令牌，配合平臺自己的控制元件和系統字型。

## 6. 預設安靜

使用能解決問題的最輕量的反饋：持續存在的狀態就地顯示，已完成的操作用輕提示（toast），檢視功能受限時用橫幅，只有使用者必須做決定時才用對話方塊。絕不為了告知資訊而打斷使用者。視窗之外的通知需要使用者主動開啟，並說明為什麼會收到這條通知。

## 7. 所有應用共用一套系統

用令牌，不寫具體值：應用程式碼中不寫死顏色、圓角或時長。用元件，不做一次性的實現。品牌層是同系列應用唯一可以改動的部分（[品牌](brand.md)）。設計需要系統裡沒有的東西時，先把它加進系統。

## 8. 無障礙從一開始就做進去

兩套主題下，文字都達到 WCAG 2.2 AA（4.5:1），圖形和焦點指示達到 3:1。所有功能都能用鍵盤操作，並有清晰可見的焦點環。動效遵循“減弱動態效果”設定。元件自帶 ARIA 角色，應用不必自己記著新增（[無障礙](accessibility.md)）。

## 9. 每種語言都放得下

介面提供十種語言。佈局按最長的文字來設計（俄語和德語比英語長 30–60%；中文和日文更短，但字形更高），數字和日期按語言區域格式化，任何文字都不由片段拼接而成（[文案](content.md)）。

## 裁決分歧的規則

1. **用令牌，不用具體值**。缺少某個值時，就新增一個令牌，並給出兩套主題的取值。
2. **深色值相同、用途不同，就用不同的令牌**。懸停底色、浮動面板和選中的分段在深色模式下看起來都是 `#262626`，但在淺色模式下需要不同的值（`surface.raised`、`surface.popover`、`component.segmentActive`）。角色要儘早拆分。
3. **每個區域只有一個主要操作**。次要操作用次要按鈕或幽靈按鈕；破壞性操作用危險按鈕，並且絕不作為預設焦點。
4. **純圖示控制元件需要文字說明**（`aria-label` 和懸停提示），而且必須是容易辨認的圖示。
5. **載入失敗時，原本有內容的頁面絕不變成空白**。
6. **會改動電腦的操作，要麼先確認，要麼可以撤銷**——最好兩者兼有。
