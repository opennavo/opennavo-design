# アクセス可能

ターゲットは WCAG 2.2 AA は、両方のテーマで作成されます。ほとんどのトークンとコンポーネントに組み込まれています。このページでは、どのようなものなのかをリストしています。
アプリは、やり直しをしてはならない。

<a id="contrast"></a>

## コントラスト

- テキスト4.5:1は、小さなバッジやホバーの塗りつぶしを含む実際の背景に対して、; 大きい表示テキスト(24 px +、または)
  19 px + 600) 3:1. トークンテストは、ペアを強制します [カラー › コントラスト](color.md#contrast).
- 意味、チャートマーク、入力境界、フォーカスリングを運ぶアイコン: 3:1.
- 装飾的なテキスト(`text.disabled`、透かし)は情報を運びません。

<a id="keyboard"></a>

## キーボード

- 視覚的な順序でタブで到達できるものすべて; 焦点を当てるものは見えない。
- **焦点リング:** `shadow-focus-ring` お問い合わせ `:focus-visible` — 表面色に2pxのギャップと2pxのサンゴリング。
  同じくなく削除しないでください。
- **複合ウィジェット** フォーカスをロッキング(タブの停止、1つの矢印)を使用してください。 セグメント化されたコントロール()`radiogroup`), タブ
  (`tablist`)、破片棒、メニュー(`menu` とりあえず `menuitem` / `menuitemradio`)、コマンドパレット()`combobox` +
  `listbox`).
- **オーバーレイ** 開いた、トラップタブでフォーカスを移動し、エスケープを閉じて、それらを開いた要素にフォーカスを戻します。
  Script-movedフォーカスは、ユーザーがポインタでオーバーレイを開くとき、リングを表示しません。
- **ショートカット** プラットフォーム(⌘K search, ⌘, settings, ⌘F はビューで見つけます, エスケープバックアウト) で表示します。
  メニューとヒントは、必要なくありません。

<a id="screen-readers"></a>

## スクリーンの読者

- semantic要素を最初に使用して下さい(`button`, `a`, `nav`, `main`, `h1`–`h3`, `table`; コンポーネントは、その場所だけの役割を追加します。
  HTML どれも持っていません。
- アイコンのみの制御を持っています `aria-label`; 装飾的なアイコンと名前の横にあるアプリのアイコンは、 `aria-hidden`.
- 現在のページ `aria-current="page"`; トグル `role="switch"` とりあえず `aria-checked`; 忙しいボタン `aria-busy`.
- トースト:失敗 `role="alert"`, 他は、礼儀のライブ領域. 進捗は、同等のテキストを持っています ("1.2 の 3.4 GB).
- グラフはテキストの要約またはテーブルの同等性を持っています。スパークラインは現在の値でラベル付けされます。

<a id="motion-and-timing"></a>

## モーションとタイミング

- 「リデュース・モーション」を尊重する(`base.css` ハンドル CSS; JavaScript アニメーションはチェックしなければなりません `matchMedia`).
- 恐ろしい間に一時停止をトーストします。 何も重要なことは、それを再び見つける方法なしでタイマーに消えません(歴史、
  タスクリスト)

<a id="pointer-and-touch"></a>

## ポインターとタッチ

- 最小24 x 24 pxの高密度デスクトップUI、プライマリコントロール32 px、プライマリモバイルWebアクション44 pxのターゲットをターゲットにします。
- Hoverはキーボードとタッチユーザーが到達できないことを何も明らかにしません。

## 言語

色、位置、または単独で意味: ステータスは、アイコンと単語で色をペアリングします。
