# 交互模式

> 英文原文：[patterns.md](../patterns.md)。两者不一致时以英文版为准。

本篇讲组件如何组合成页面。每个模式都写明了用到的组件，组件细节见[组件](../components.md)（暂为英文）。

## 导航

- **侧边栏**（`OnSidebar`、`OnNavItem`）：最上方是品牌标志，然后是若干分组，每组有一个 `text-label` 标题（浏览、清单、工具、我的……），设置固定在最下方。当前项使用 `component.navActive` 和 `aria-current="page"`。数量靠右对齐，使用 `text-ink-tertiary`；需要用户注意的数量改用珊瑚色徽标；只提示“有新内容”、不需要数字时，用一个圆点。
- **工具栏**（`OnToolbar`）：桌面应用中，左侧是后退/前进和刷新（网页上由浏览器提供），右侧是带 `⌘K` 提示的搜索入口，再往右是全局开关（主题；网页上还有语言）。
- **命令面板**（`OnCommandPalette`，`⌘K` / `Ctrl K`）：操作和跳转目标排在前面，第一行是“See all results for ‘q’”（“查看‘q’的全部结果”），按 Enter 打开完整的结果页；其余条目排在下面。方向键移动，Enter 打开，Escape 关闭并把焦点还给原来的位置。
- **标签页**（`OnTabs`）用来切换同一对象的不同视图（例如一个应用的概览、版本、依赖、详情）；每个视图有自己的 URL 时，标签页就是链接。**分段控件**（`OnSegmented`）用于在视图内部筛选或切换模式（时间段、排序、“全部/成功/失败”）。
- **面包屑**（`OnBreadcrumb`）出现在从列表进入的详情页上。
- 每个视图都有 URL（桌面端的路由也一样），这样深层链接、后退/前进和恢复都能正常工作。

## 页面结构

1. 页面头部（`OnPageHeader`）：`text-title1` 标题；一行次要文字，写出关键信息（数量、上次检查时间）；页面操作靠右对齐（主要操作放在最后）。
2. 视图功能受限时（离线、部分失败），可以在页面头部正下方放一条横幅。
3. 区块（`OnSectionHeader`）：`text-headline` 标题，一行简短的副标题（三级文字），右侧放“查看全部 →”。
4. 右侧栏（`OnRailPanel`、`OnRailSection`）承载摘要和次要操作；在主内容栏完成任务时，不需要用到右侧栏里的任何内容。

## 列表、卡片和表格

- **卡片**用于浏览（图标、名称、一行摘要、两三个统计数字、一个操作）。整张卡片就是链接；卡片里的操作按钮要阻止事件冒泡。
- **行**用于需要逐项操作的紧凑列表（更新、历史记录、已安装的应用）：左侧是图标、名称和元信息，中间是状态标签（chip），右侧是操作；破坏性操作放在行的⋯菜单里。
- **表格**（`OnTable`）用于需要按列比较或排序的场合；数字列右对齐，并使用 `tabular-nums`；勾选框放在第一列；长表格的表头固定。
- 长列表用分页（`OnPagination`），不用无限滚动，这样当前位置可以被链接，也保持稳定。
- **调整条件时保留内容**：查询、排序、筛选条件或页码变化时，继续显示之前的结果（必要时调暗），直到新结果到达；为可选的计数行预留位置，避免内容跳动。

## 搜索

- 工具栏里的搜索入口打开命令面板；搜索页显示完整结果，筛选项用分段控件或标签呈现。
- 用户输入时结果实时更新，中途不清空；“No results for ‘q’”（“没有找到‘q’的结果”）要附带一条具体的建议（换一种拼写、用英文名、换一个来源）。

## 设置和表单

- 设置按卡片分组，每张卡片由若干行组成（`SettingRow` 模式）：左侧是名称和可选的一行提示，右侧是控件，行与行之间用 `border.subtle` 分隔。
- **改动立即生效**——开关、分段控件、菜单都是如此。设置里没有“保存”按钮；某项改动失败时，恢复原值，并用轻提示（toast）说明原因。
- 按选项数量选择控件：开/关用开关，两到四个互斥选项用分段控件，更长的列表（比如语言）用菜单，并勾选当前选项。
- 文本输入在失去焦点或提交时校验，绝不在每次按键时校验；错误用 `text-status-danger` 显示在字段下方，并写明怎么改，例如“Use a full https:// address”（“请填写 https:// 开头的完整地址”）；字段保留已输入的值。
- 网页上的表单只有一栏，字段标题在输入框上方；必填字段全部有效之前，提交按钮保持禁用，并用提示说明还缺什么。

## 反馈

| 场景                                 | 用法                                                                     |
| ------------------------------------ | ------------------------------------------------------------------------ |
| 操作已完成（已复制、已添加、已安装） | 轻提示，成功或中性样式，4 s 后自动消失，悬停时暂停计时                   |
| 操作失败                             | 轻提示，写明原因；可能的话附带一个操作（重试、查看日志）                 |
| 视图功能受限（离线、数据不完整）     | 页面头部下方的横幅，说明哪些功能仍然可用                                 |
| 需要用户做决定                       | 对话框（`OnConfirm`、`OnModal`）                                         |
| 正在执行长任务                       | 就地显示进度（行、卡片或任务面板）；如果任务转到后台继续，菜单栏里也显示 |
| 窗口关闭期间发生了某件事             | 系统通知，仅在用户开启通知时发送                                         |

同时最多显示三条轻提示；失败会立即向读屏软件播报（`role="alert"`），其余的以礼貌模式（polite）播报。

## 破坏性操作和改动系统的操作

1. 说清会发生什么，并列出将被移除或改动的内容及其大小。
2. 默认选可恢复的方式：移到废纸篓；停用登录项，而不是删除；保留回滚的余地。
3. 确认按钮写明动作，例如“Uninstall”（“卸载”）、“Move 14 items to Trash”（“将 14 个项目移到废纸篓”），并使用危险样式；默认焦点放在“取消”上。
4. 操作之后：结果立即就地显示；可以撤销时，弹出带“撤销”的轻提示；同时在历史记录中留下一条记录。
5. 需要管理员权限的操作，开始之前就要说明；密码提示框要写明用途。

## 加载、进度和结果

- 视图首次加载：使用形状与内容一致的骨架屏（`OnSkeleton`），不要整页显示加载转圈。
- 刷新、调整条件、后台重新加载：保留当前内容，最多显示一个小小的进度提示。
- 长任务一有数字（字节数、项目数）就显示确定进度，并用文字说明当前步骤；取消不会造成问题时，允许用户取消。日志可以查看，但默认折叠。
- **结果即时呈现**：任务一结束，所有显示该对象的地方（行、详情页、侧边栏计数、菜单栏）都立即用任务自身的结果更新，而不是等到下一次定时刷新。

## 空状态、错误和离线

- **空状态**（`OnEmpty`）：一个图标；一个简短的标题，例如“Your list is empty”（“清单是空的”）；一句话说明怎样把它填满；有对应的操作时，再放上这个操作。
- **错误**（`OnErrorState`）：用平实的话说明什么失败了，提供“重试”，不显示堆栈信息；原本有内容的视图刷新失败时，改为显示横幅并保留内容。
- **离线**（`OnOffline`）：缓存的内容仍然可用；需要联网的功能，在它本该出现的位置说明这一点。

## 权限

- 在真正需要的时候再申请权限，用一句话说明原因，以及哪些内容会保持私密。
- “开启”会打开系统设置中对应的面板；一个小的浮动引导会说明要拖动或打开什么，并且不会抢走系统设置的焦点。
- 用户回来后，视图会重新检查并自动继续；如果 macOS 要求重新启动应用，视图会说明这一点并提供重启选项。
- 绝不纠缠用户：用户拒绝授权后，只留下一行带“开启”按钮的安静提示，而不是反复弹出对话框。

## 菜单栏项目和浮窗（macOS）

- 菜单栏项目使用模板图像，画法与系统项目一致；文字和图表遵循系统菜单栏的样式。
- 点击项目会在其下方打开浮窗；再次点击或点击其他任何地方即关闭。浮窗绝不激活主窗口，也绝不抢走用户当前所用应用的焦点。
- 浮窗是紧凑的卡片（`surface.card`、`rounded-panel`），放最有用的三到五行内容、一个主要操作，以及一个在主窗口中打开完整视图的链接。

## 新手引导

只用一个检查清单页面：每项要求占一行，包含状态图标、这项要求是什么，以及修复操作；必需的各行全部通过后，主按钮“开始使用”才可点击，在此之前用一句话说明还缺什么。可选步骤可以跳过，之后也能在设置里找到。

## 网站专属规则

- 网站绝不要求注册账号。每位访客各自的选择（主题、隐私授权、语言建议、保存的清单）都存在浏览器里。
- “在应用中打开”链接会请桌面应用先展示它将要做什么；对于网页发起的任何请求，应用在执行之前都会先请用户确认。
- 语言建议只出现一次，可以关闭，并且绝不自行跳转。
